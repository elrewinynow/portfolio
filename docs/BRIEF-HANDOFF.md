# بريف جلسة التشخيص التسويقي

## الحالة

النسخة المحلية تعمل. **نشر الإنتاج BLOCKED** إلى حين فحص نوع خدمة Render والتخزين الدائم في الحساب الصحيح واختيار طريقة التخزين. الحساب المتصل بأداة Render ليس حساب الموقع بحسب تأكيد المالك. لم تتغير ملفات الصفحات الحالية، ولم يُدمج الفرع في main. لا يكفي رفع ملفات الواجهة إلى Static Site لتشغيل الخادم.

المصدر الأساسي عند بدء العمل: `elrewinynow/portfolio`، commit `c2f8eb0775325fadfe888f3cdeecb98744430f65`. لم توجد ملفات AGENTS.md في المستودع؛ اتُّبعت تعليمات المالك المقدمة في المحادثة. الموقع HTML/CSS ثابت دون إطار عمل أو خادم أو قاعدة بيانات موثقة. ترويسات الموقع العام تضمنت `rndr-id`؛ إعدادات خدمة Render نفسها غير متاحة. GitHub Pages مفعلة أيضًا من main، لكنها ليست دليلًا على إعداد خدمة النطاق الخاص.

## التشغيل المحلي

يتطلب Node.js 24 أو أحدث، دون مكتبات إضافية أو تثبيت حزم:

```powershell
npm start
# افتح http://127.0.0.1:3000/Brief
npm test
```

الخادم المحلي يستمع على loopback فقط. Ctrl+C يوقف الخادم ويغلق SQLite. مجلد `data/` مستبعد من Git، ويُنشأ عند التشغيل. لا تُخزّن كلمات مرور أو بيانات عملاء في المستودع.

## تجربة العميل

ست خطوات RTL، هوية أحمد الرويني وشعاره الحالي، ومتوافقة مع الهاتف. المطلوب: اسم النشاط، المسؤول، وسيلة تواصل واحدة صحيحة على الأقل، المنتج/الخدمة، التحدي، وهدف أو هدفان. باقي الأسئلة اختيارية باستثناء توضيح «آخر» عند اختياره. حفظ الإجابات في ذاكرة الصفحة أثناء التنقل والعودة، مع تنبيه قبل مغادرتها إذا لم تُرسل؛ **لا يوجد حفظ مسودة بعد إغلاق الصفحة أو إعادة تحميلها** ولا يُستخدم localStorage. هدف ٣–٥ دقائق تقدير تصميمي ولم يُقَس على عملاء حقيقيين.

رسالة النجاح لا تظهر إلا بعد استجابة الخادم بمعرف محفوظ، ولا تؤكد الحجز. الحجز يظل على نظملي. لا حسابات إدارية أو واجهات قراءة عامة أو dashboard ضمن هذا الفرع.

## التخزين ونقطة الإرسال

SQLite محليًا: `data/briefs.sqlite`؛ الإنتاج يحتاج مسارًا على **قرص دائم فعلي**. جدول `brief_submissions`:

| العمود | الغرض |
|---|---|
| `id` | UUID ثابت للبريف وإيصال العميل |
| `request_key` | UUID فريد لإعادة نفس الطلب دون تكرار الحفظ |
| `intent_hash` | بصمة الإجابات بعد التطبيع، ورفض نفس المفتاح بإجابات مختلفة |
| `submitted_at` | وقت الخادم UTC بصيغة ISO |
| `status` | `new` مبدئيًا؛ حالات محجوزة لاحقًا reviewing/reviewed/archived |
| `schema_version` | 1 لتسهيل ترحيل البيانات لاحقًا |
| `brand`, `contact_name`, `phone`, `email` | حقول أساسية للبحث لاحقًا |
| `answers_json` | كل الإجابات بمفاتيح واضحة في `Brief/schema.js` |

الحالة `new` تعني «جديد». الفهرس على الحالة ووقت الإرسال. جدول `request_limits` يحتفظ بعدادات قصيرة العمر بمفاتيح HMAC، لا بعنوان IP صريح. لا تُسجَّل إجابات العملاء في logs. يستخدم الخادم SQL بمعاملات، ومعاملة `BEGIN IMMEDIATE` لحفظ الرد ونتيجة التكرار والعداد معًا.

`GET /api/brief/challenge`: رمز موقّع، صلاحية ساعتان، انتظار ٣ ثوانٍ على الأقل. `POST /api/brief`: JSON بحد 32 KiB، Origin مطابق، Idempotency-Key، تحقق مستقل من جميع الحقول، honeypot، رفض رمز غير صحيح. الحدود: 60 طلب رمز/ساعة، 30 محاولة إرسال/10 دقائق، 5 بريفات جديدة/ساعة لكل عنوان اتصال. التكرار الناجح لا يُنشئ سجل بريف جديدًا. هذه مقاومة أساسية للروبوتات؛ ليست CAPTCHA ولا تمنع مهاجمًا موزعًا.

لا يتم جلب الروابط المقدمة من الخادم، ولا استقبال ملفات أو صلاحيات دخول. تُقبل روابط http/https العامة الشكل فقط؛ تظل عامة الوصول مسؤولية صاحب الرابط. لا يمكن لخادم النموذج التأكد من أن تقريرًا غير محمي فعليًا دون فتحه.

## ما يلزم قبل نشر الإنتاج

1. معرفة نوع خدمة Render والفرع المنشور وأوامر البناء والتشغيل، والتأكد من مصدر IP الموثوق خلف وسيط Render. الخادم المحلي يعتمد `socket.remoteAddress` ويتجاهل X-Forwarded-For غير الموثوق؛ خلف proxy قد يشارك الزوار نفس العداد. يجب تكييفه وفق إعداد الاستضافة الفعلي قبل النشر، وعدم الثقة العمياء بترويسات العميل.
2. إن كانت Static Site دون backend، فهي لا تشغّل Node أو SQLite. أبسط مسار يتوافق مع هذه النسخة: Web Service واحدة تشغّل الموقع الحالي والخادم مع قرص دائم لـ SQLite. **هذا قرار تغيير استضافة وتكلفة يحتاج موافقة المالك؛ لم يُنفذ.** لا تنشر SQLite على نظام ملفات Render المؤقت أو خطة لا تدعم قرصًا دائمًا. بديل الحفاظ على Static Site: backend منفصل مع تخزين دائم وتهيئة CORS/حماية موثوقة؛ لم يُنشأ لأن الخدمة والحساب لم يُختارا.
3. إعداد `NODE_ENV=production`، `PUBLIC_ORIGIN=https://elrewiny.com`، `BRIEF_DB_PATH=<persistent-mount>/briefs.sqlite`، و`BRIEF_SECRET` عشوائي سري 32 حرفًا أو أكثر في إعدادات الخادم فقط. لا تدخل القيم السرية في Git أو الواجهة. أمر التشغيل `npm start` وNode >=24. الخادم يخدم `/Brief` مباشرة مع الحفاظ على مسارات الصفحات والملفات الحالية. لا توجد حاجة إلى DNS لربط المسار على خدمة الموقع نفسها، لكن أي انتقال للخدمة يحتاج خطة مستقلة وموافقة.
4. SQLite مناسبة لنسخة خادم واحدة على قرص محلي دائم. لا تستخدم عدة خدمات أو عدة أقراص منفصلة كأنها قاعدة واحدة. تهيئة نسخ احتياطية مشفرة باستخدام SQLite backup API أو أداة تراعي WAL، واختبار الاستعادة، وتحديد سياسة الاحتفاظ بالبيانات قبل استقبال بيانات العملاء.
5. نشر تجريبي، اختبار المسارات القديمة والبريف والإرسال والتكرار والرفض عبر وسيط الاستضافة، ثم إعادة تشغيل/نشر والتأكد من بقاء سجل اصطناعي. لا تعتبر النشر ناجحًا دون هذا الاختبار. لا ترفع بيانات الاختبار المحلية إلى الإنتاج.

تكلفة استرشادية تحققت من صفحة Render الرسمية في 2026-11-26: أقل compute مدفوع معروض $7/شهر، والقرص $0.25/GB/شهر؛ مثال 1 GB مع compute يصبح $7.25/شهر قبل الضرائب وأي استخدام إضافي. السعر الفعلي يتأكد في حساب المالك قبل الإنشاء. المصادر: https://render.com/pricing ، https://render.com/docs/disks ، https://render.com/docs/static-sites . لم تُنشأ خدمة مدفوعة أو قاعدة خارجية.

## ربط الداشبورد لاحقًا

يقرأ backend خاص محمي بهوية المالك من نفس `brief_submissions`، مع pagination وفلاتر الحالة وتاريخ الإرسال. إن ظل التخزين SQLite، يمكن لخادم الموقع نفسه تقديم API إدارية محمية لاحقًا للداشبورد على subdomain؛ لا تشارك ملف SQLite مباشرة أو تعرّضه للتحميل. إذا لزم backend مستقل أو عدة نسخ، تُرحَّل البنية إلى قاعدة مشتركة مثل PostgreSQL أولًا. المصادقة والصلاحيات وCORS وDNS ليست منفذة في هذه المرحلة. لا توجد نقطة GET عامة لاستعراض الردود.
