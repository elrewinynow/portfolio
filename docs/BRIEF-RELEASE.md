## PASS مثبت

- `npm test`: خمس مجموعات PASS، صفر FAIL، صفر SKIPPED. التزامن يشمل اتصالي SQLite مستقلين لمسار Worker واختبار عمليتين مستقلتين للخادم المحلي.
- `wrangler deploy --dry-run`: حزمة Worker صالحة.
- نشر Worker فعليًا على workers.dev دون routes أو custom domains.
- عشر فحوص HTTP حية في `tests/live-smoke.mjs`: صحة القاعدة، CORS المحددة، رفض origin أجنبي، عدم وجود قائمة عامة للردود، إصدار رمز التحقق، رفض تواصل غير صحيح وhoneypot، إنشاء واحد وإعادتان متزامنتان بنفس الهوية، ورفض تغيير intent بنفس المفتاح.
- D1 أكدت وجود سجل اختبار اصطناعي واحد بمعرف `39925079-e24b-45c2-b386-afb8aa4983ae` وحالة `new` ووقت خادم `2026-11-26T13:27:12.811Z`؛ لا بيانات عملاء حقيقية مستخدمة.
- إعادة نشر Worker ثم الاستعلام عن السجل نفسه أثبتت بقاء البيانات.
- تصدير قاعدة D1 واستعادتها في SQLite نظيفة في الذاكرة: نفس السجل والحالة والمعرف. لم تتم استعادة أو استبدال قاعدة الإنتاج. نسخة التحقق محليًا خارج المستودع في `../validation/brief-cloudflare-20261126/`، ولا تُنشر على الموقع.

سجل الاختبار موسوم صراحة بأنه اختبار وليس طلب عميل. لم نحذفه أو نغيّر حالة سجل تاريخي.

## التشغيل والصيانة

Node >=24 و`npm start` للمعاينة المحلية. `npm test` للاختبارات. تحديث Worker يكون بأداة Wrangler الرسمية من `cloudflare/wrangler.jsonc` بعد الاختبارات. تحديث الواجهة يُنشر من `portfolio/main` عبر الربط التلقائي الموجود مع Render. تحديث Worker لا يمس بيانات D1. لا تُعد تطبيق migrations مدمرة على بيانات العملاء.

القيم `new/reviewing/reviewed/archived` تعني جديد/قيد المراجعة/تمت المراجعة/مؤرشف للداشبورد المستقبلية. الداشبورد لاحقًا تقرأ نفس D1 عبر API محمية بصلاحيات المالك؛ لا توجد نقطة قراءة عامة حاليًا. تحديد سياسة الاحتفاظ والنسخ الاحتياطي الدوري يتم قبل توسع الاستخدام؛ تصدير النسخة التجريبية ليس جدول نسخ احتياطي دوريًا.

## تحقق الواجهة

نشر الواجهة واختبار `/Brief` والإرسال من المتصفح على النطاق الفعلي يتمان بعد وصول commit إلى main. الحالة التفصيلية النهائية تُضاف بعد اكتمال الاختبار؛ لا يُعتبر فحص API وحده دليلًا على اكتمال النشر المرئي.
