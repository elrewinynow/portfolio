# حفظ البريف على Cloudflare — الخطة المجانية

هذا المسار يحل محل خطة Render المدفوعة بعد رفض المالك أي تكلفة إضافية. تبقى خدمة `elrewiny` الحالية على Render كما هي؛ الواجهة تُنشر من `portfolio/main`، والـAPI تعمل في Worker منفصل بعنوان workers.dev دون تغيير DNS أو ربط Subdomain مخصص. الداشبورد غير منفذة.

## الموارد التي جرى التحقق منها

- الحساب المستضيف للدومين: `046dfdfbbef5bccb93d469ff723993ff`.
- Workers Free — Current plan — $0، تحقق من لوحة الحساب في 2026-11-26. لم يتم الضغط على Upgrade أو إضافة بيانات دفع.
- قاعدة مستقلة: `elrewiny-brief`، ID `f591c3ae-44b8-45b3-9bbc-c40a4acce92c`.
- جداول القاعدة وفهارسها وtriggers مطابقة لـ`cloudflare/schema.sql`، وتم التحقق من أسمائها عبر sqlite_master من لوحة D1.
- موارد `mailflare` الموجودة مسبقًا غير معدلة.

## الكود والتخزين

`cloudflare/worker.js` يستخدم نفس `Brief/schema.js` للتحقق من المدخلات. `cloudflare/wrangler.jsonc` يحدد الـWorker وبايندنج `DB` للقاعدة. لا توجد مفاتيح أو أسرار في الواجهة أو المستودع. رمز التحقق العشوائي لا يُحفظ كنص: تخزن القاعدة SHA-256 فقط، مع ربطه بعنوان العميل الذي توفره Cloudflare، وعمر صلاحية ساعتين. عنوان IP يُحوَّل إلى بصمة باستخدام salt عشوائي داخل قاعدة البيانات، ولا تُخزَّن الترويسة الأصلية.

جدول `brief_submissions` يحتفظ بمعرف UUID وRequestKey فريد وبصمة الإجابات ووقت UTC وحالة `new` (جديد)، وschema_version وبيانات النشاط والتواصل وجميع الإجابات بصيغة JSON. تضمن قاعدة البيانات التكرار الآمن واستخدام رمز التحقق مرة واحدة؛ تحفظ الكتابة والعدادات في نفس العملية باستخدام triggers، دون معاملة متعددة الخطوات غير مدعومة في D1.

الجداول المساعدة: `brief_challenges` للتحقق المؤقت، `brief_limits` للعدادات، و`brief_settings` لـsalt العشوائي. هذه سجلات تشغيل فعلية وليست ردود عملاء أو بيانات قبول مصطنعة.

## الحدود والحماية

- Origin المسموح به للواجهة: `https://elrewiny.com` فقط؛ preflight يسمح بـPOST وContent-Type وIdempotency-Key فقط، دون credentials/cookies.
- حجم الطلب 32 KiB، وتحقق خادمي مستقل، وhoneypot، وانتظار 3 ثوانٍ قبل استخدام رمز التحقق.
- لكل عنوان عميل: 30 رمزًا/ساعة، 30 محاولة إرسال/10 دقائق، و5 ردود جديدة/ساعة.
- حدود تطبيق إضافية للحفاظ على الحصص المشتركة بالحساب: 1000 رمز تحقق/يوم، 3000 محاولة إرسال/يوم، و100 رد جديد/يوم.
- رموز التحقق والعدادات المؤقتة المنتهية تُنظَّف عند طلب رمز جديد. لا توجد نقطة عامة لقراءة أو تصدير الردود.
- عند بلوغ حدود التطبيق يرجع 429؛ وعند تعذر D1 أو نفاد حصتها يرجع 503، ولا تظهر رسالة نجاح. تبقى الإجابات في الصفحة لإعادة المحاولة.

المجانية ليست استخدامًا بلا حدود: حصص الحساب مشتركة مع تطبيقاته الأخرى. لا ترقية تلقائية أو خطة مدفوعة جرى تفعيلها. المصادر الرسمية: https://developers.cloudflare.com/workers/platform/pricing/ و https://developers.cloudflare.com/d1/platform/pricing/ .

## النشر والتحقق

أداة النشر الرسمية Wrangler، عند توفر تسجيل الدخول للحساب الصحيح:

```powershell
npx wrangler deploy --config cloudflare/wrangler.jsonc
```

تطبيق schema يتم مرة واحدة على القاعدة الجديدة من الملف المرفق. لا تُعاد تهيئة القاعدة أو استبدال بياناتها عند تحديث Worker. يجب ضبط `Brief/config.js` بعنوان Worker الفعلي قبل دمج الواجهة في main. لا يحتاج ذلك إلى تعديل إعداد خدمة Render أو DNS.

الاختبارات المحلية: `npm test`؛ خمس مجموعات PASS، بينها Worker مع SQL وtriggers فعليين على اتصالي SQLite مستقلين، وتحقق من rollback وreplay واختلاف intent وربط التحقق بالعميل وفشل الحصص، مع بقية اختبارات الواجهة/الخادم المحلي. توافق Cloudflare الفعلي يُثبت بعد نشر Worker وتجربة النموذج من الموقع والتحقق من السجل في D1. لا تساوي الاختبارات المحلية اختبار D1 عن بعد.

لا تضع ملف القاعدة أو صادرات الردود في Git. التخزين المحلي Node/SQLite باقٍ للتطوير فقط؛ التخزين المعتمد للعملاء في هذا المسار هو D1. الداشبورد لاحقًا تستخدم نفس القاعدة عبر API محمية بمصادقة وصلاحيات المالك؛ لا تضف قراءة عامة للردود.
